# 진입 · 상호작용 · 라우트 전환 — 재사용 컴포넌트 카탈로그

담당 B. toss.im 을 프레임으로 관찰해 **우리 코드베이스에 그대로 넣을 수 있는 React 컴포넌트**로 환산한 문서다.
각 항목은 컴포넌트 시그니처 / 지시문 / 레퍼런스 이미지(프레임 번호) / 레퍼런스 영상(webm) / 우리 사이트 적용 위치를 갖는다.

관찰일 2026-08-22. 뷰포트 1440×900, `deviceScaleFactor 1`.
코드는 고치지 않았다. 프레임에서 보이지 않는 것은 **「관찰 못함」**으로 남겼다.

## 프레임 시각 읽는 법

| 모드 | 000 | 이후 |
|---|---|---|
| `load --every N` | 첫 촬영 | 001 = +N ms, 002 = +2N ms … |
| `hover` / `click` | 트리거 직전(휴식) | 001 = +45, 002 = +90, 003 = +135, 004 = +180, 005 = +225, 006 = +345, 007 = +465, 이후 +120씩 |

이 ms 는 **명목 대기 시간**이다. 스크린샷 자체의 소요 시간이 더해지므로 실제 경과는 항상 그보다 크다.
따라서 「+45ms에 72%」 같은 수치는 **상한이 아니라 하한**으로 읽어야 한다.

이 문서가 쓴 캡처 슬러그: `toss-load-20`, `toss-scroll-64-120`, `b-rail-hover`, `b-rail-click`,
`b-nav-biz-hover`, `b-navlink-hover`, `b-dl-click`, `b-dlbtn-hover`, `b-lang-click`,
`b-route-newsroom`, `b-route-company`, `b-company-load`,
그리고 우리 쪽 `b-our-load`, `b-our-scroll`, `b-our-route`, `b-our-tab`, `b-our-expand`, `b-our-navhover`.

`_b-*.jpg` 는 원본 PNG를 확대·잘라 붙인 보조 시트다. 시트 격자로는 2px 눈금이나 반투명 카드가 판별되지 않아 따로 만들었다.

## 1. `<HeroInsetCanvas>` — 인셋 캔버스가 스크롤에 따라 풀블리드로 열린다

```jsx
<HeroInsetCanvas
  inset={16}          // 좌우 여백 px (진행도 0에서)
  top={64}            // 헤더 높이만큼의 위 여백 px
  radius={40}         // 모서리 반경 px (진행도 0에서)
  span="200vh"        // 이 스크롤 거리 동안 0 → 1 로 간다
  ease={(t) => 1 - (1 - t) ** 4}   // 관찰된 곡선
  poster="/img/hero_light@2x.webp"
>
  <video … />
</HeroInsetCanvas>
```

### 지시문

무대는 **뷰포트 자체**이고, 교체되는 것은 아무것도 없다. 바뀌는 것은 **하나의 미디어 상자의 치수**뿐이다.

문서 최상단(진행도 0)에서 상자는 좌우 16px, 위 64px(헤더 높이), 아래 24px 만큼 안쪽으로 들어가 있고
모서리 반경은 40px 이다. 흰 배경이 상자 둘레를 액자처럼 감싼다.
스크롤이 내려가는 동안 이 상자는 **좌우 여백 16→0, 위 여백 64→0, 폭 1408→1440, 높이 812→900,
반경 40→0** 으로 동시에 보간되어 결국 뷰포트를 꽉 채운다. 되감으면 그대로 되돌아온다.

트리거는 클릭도 타이머도 아니고 **`window.scrollY` 값 자체**다. 관성이나 딜레이가 없다.
어느 스크롤 위치에서 멈추든 상자는 그 위치에 대응하는 크기로 정지해 있다.
스크롤 점프 후 320ms 를 기다린 뒤 측정해도 값이 그대로였다 — 프레임마다 목표값을 쫓아가는 lerp 가 아니다.

진행도–스크롤 관계는 선형이 아니다. 측정값이 **`p = 1 - (1 - scrollY/1800)^4`** 에 소수점 아래까지 들어맞는다.

| scrollY | 반경(측정) | `40·(1-sy/1800)^4` | x | 폭 |
|---:|---:|---:|---:|---:|
| 0 | 40.000 | 40.000 | 16.00 | 1408.0 |
| 100 | 31.825 | 31.825 | 12.73 | 1414.5 |
| 300 | 19.290 | 19.290 | 7.72 | 1424.6 |
| 600 | 7.901 | 7.901 | 3.16 | 1433.7 |
| 900 | 2.500 | 2.500 | 1.00 | 1438.0 |
| 1200 | 0.494 | 0.494 | 0.20 | 1439.6 |
| 1600 | 0.006 | 0.006 | 0.00 | 1440.0 |

즉 **1800px(= 뷰포트 높이의 정확히 2배) 동안 ease-out-quartic**. 절반(900px)을 지나면 이미 93.75%가 끝나 있다.
체감상 "처음 한 화면에서 확 열리고 나머지는 미세하게 붙는" 리듬이다.
1800 = 2 × 900(뷰포트 높이)이므로 `200vh` 로 쓰는 것이 안전하다. 다른 뷰포트 높이에서의 재검증은 못했다.

`transform` 행렬은 `matrix(1,0,0,1,-16p,-64p)` 로 **평행이동만** 하고 `scale`은 없다(`scale: none`).
폭·높이·반경은 별도로 보간된다. 즉 영상이 늘어나 뭉개지지 않고, 액자만 벌어진다.

**로드 시점에는 이 확장이 일어나지 않는다.** `toss-load-20` 30프레임(명목 600ms) 전부에서
좌 16 / 우 1423 / 하단 875 가 한 픽셀도 변하지 않았다. 진입은 §2 가, 확장은 스크롤이 담당한다.

## 2. `<WordCascade>` — 어절이 순차로 초점을 잡는다

```jsx
<WordCascade
  as="h1"
  groups={['금융부터 일상까지', '마침내', '토스 하나로']}
  mode="opacity"      // 'opacity' | 'blur'
  step={20}           // 어절 간 지연 ms
  blur={10}           // mode='blur' 일 때 시작 blur px
  dur={240}
/>
```

### 지시문

한 줄의 카피를 **어절 그룹 단위로 쪼개, 앞에서 뒤로 순차 등장**시킨다.
고정되는 것은 **글자의 위치**다. 어절의 x·y 는 처음부터 최종 위치에 있고 한 번도 움직이지 않는다.
교체되는 것은 각 어절의 **가시성(opacity, 그리고 페이지에 따라 blur)** 뿐이다.

toss 에는 두 변종이 있고 둘 다 관찰했다.

**(a) `mode="opacity"` — 홈 히어로.** blur 없음, translate 없음, 순수 opacity.
`toss-load-20`(20ms 간격) 프레임 001 에서 「금융부터 일상까지」는 거의 불투명,
「마침내」는 눈에 띄게 옅고, 「토스 하나로」는 아직 없다. 프레임 002 에서 셋 다 최종 밝기다.
`_b-hero-textband.jpg` 로 세 어절의 x좌표가 001 과 002 에서 **완전히 동일**함을 확인했다 — 밀려 들어오지 않는다.
어절 간 지연은 한 프레임(명목 20ms) 안에 끝나므로 **20ms 미만**이라고만 말할 수 있다. 정확한 값은 관찰 못함.

**(b) `mode="blur"` — `/company` 히어로.** 이쪽이 훨씬 길고 눈에 보인다.
어절이 **강한 blur + 낮은 opacity 에서 초점을 잡으며** 들어오고,
블록(제목 → 부제 → 라벨 → 본문 헤드 → 본문 단락)이 계단식으로 이어진다.
`b-company-load`(45ms 간격)에서 「Greatness」의 가로 그래디언트 평균이
프레임 000 에 4.1 → 001 에 7.7 → 002 에 7.9(최종)로 올라간다. 즉 **어절 하나가 선명해지는 데 45~90ms**.
본문 단락은 프레임 005(+225ms)에 0.7, 006(+270ms)에 11.3(최종)이다.
따라서 **제목 블록과 본문 블록 사이의 계단 간격은 약 250ms**, 한 줄 안의 어절 간격은 45~90ms.

두 변종의 공통 규칙: **위치는 절대 움직이지 않는다.** toss 의 진입에서 translateY 는 한 번도 관찰되지 않았다.

`/` 히어로 `<h1>`(`src/pages/Home.jsx`). 지금은 **줄 단위**로 `--reveal-delay: 80 + i*80ms` 이고,
`[data-reveal]` 이 `translateY(18px) + blur(6px) + opacity` 를 400ms `--ease-enter` 로 푼다.
바꿀 점 두 가지 — **① translateY 를 뺀다**(toss 에는 없다), **② 줄이 아니라 어절로 쪼갠다**.
그리고 `/ai-college`, `/ai-college/adpx`, `/ai-college/roadmap` 각 페이지의 `<h2>` + `lead` + 본문 블록에도
**블록 간 250ms 계단**을 그대로 쓸 수 있다. 지금 우리 `revealDelay(i, 70)` 은 70ms 라 계단이 뭉개진다.

## 3. `<SectionRail>` — 좌측 세로 인디케이터 (전역 진행 표시)

```jsx
<SectionRail
  sections={[
    { id: 'intro', label: '토스' }, { id: 'transfer', label: '송금' }, /* … 11개 */
  ]}
  x={24}              // 뷰포트 왼쪽에서의 거리 px
  tick={{ w: 14, h: 2 }}
  pitch={12}          // 눈금 간 세로 간격 px
  hitWidth={72}       // 실제 클릭 영역 폭 px (시각 폭보다 훨씬 넓다)
  magnify={{ max: 40, falloff: [40, 39, 35, 29, 24, 20, 17, 16, 15] }}
/>
```

### 지시문

**무엇으로 만들어졌나.** 장식이 아니라 **11개의 앵커 링크**다. DOM 상 `a[href="#intro"]` … `a[href="#global"]`,
각각 `aria-label` 이 붙어 있고(토스/송금/자산/금융/투자/쇼핑/광고/결제/매장/일상/글로벌),
**클릭 영역은 72×12px** 인데 **눈에 보이는 것은 14×2px 의 짧은 가로 막대** 하나뿐이다.
막대는 x=24 에서 시작하고 12px 간격으로 쌓여 y=389~510 을 차지한다.
스택 중심 449.5 = 뷰포트 중심 450 — **세로 정중앙에 고정**이다.

**어떻게 움직이나 (1) 활성 표시.** 평상시 10개는 밝은 회색(휘도 ≈ 203~215), 현재 섹션 하나만 거의 검정(휘도 32).
스크롤하면 이 검정이 스택을 따라 **아래로 한 칸씩 옮겨간다**. 막대의 **길이는 변하지 않는다** — 색만 바뀐다.
색은 즉시 바뀌지 않는다. `toss-scroll-64-120` 프레임 008 에서 인접한 두 눈금이 동시에 **137 과 110** 이라는
중간 휘도였고, 프레임 014 에서도 **187 과 129** 였다. 이 프레임들은 스크롤 점프 후 **120ms 를 기다린 뒤** 찍은 것이므로
활성 색 전환은 **120ms 보다 길다**. 정확한 지속 시간은 관찰 못함.

**어떻게 움직이나 (2) 호버 확대.** 레일에 커서를 올리면 **막대 길이가 거리에 따라 늘어나는 볼록 렌즈**가 된다.
`b-rail-hover`(3번째 항목 「자산」 호버) 정착 상태의 길이(px):

| 커서로부터 거리 | 0 | ±1 | ±2 | +3 | +4 | +5 | +6 | +7 | +8 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 막대 길이 | **40** | 39 | 35 | 29 | 24 | 20 | 17 | 16 | 15 |

휴식 상태는 전부 14px 다. 즉 **최대 +26px, 6칸쯤 가면 원래 길이로 수렴**하는 종형 감쇠다.
색은 **호버한 항목만** 검정이 되고 이웃은 회색 그대로다(±1 항목의 휘도는 205 로 불변).
동시에 **그 항목의 텍스트 라벨이 막대 오른쪽 x≈78 위치에 페이드인**한다. 라벨은 호버한 하나에만 나온다.

타이밍: 프레임 001(+45ms)에서 길이가 이미 29 / 31 / 32 / 31 / 28 …, 정착값 대비 **약 70% 진행**.
프레임 002(+90ms)에 정착. 라벨은 001 에 회색(휘도 109) → 002 에 검정(32).
70%@45ms + 완료@90ms 는 **약 100~130ms 의 ease-out** 과 맞는다. 정확한 곡선은 관찰 못함.

**어떻게 움직이나 (3) 배경 반전.** 어두운 섹션 위에서는 눈금이 밝은 회색, 활성 눈금이 흰색으로 뒤집힌다
(`_b-leftrail.jpg` 프레임 044). 위치·간격은 그대로다.

**언제 나타나나.** 진입 첫 프레임부터다. `toss-load-20` 프레임 001 — 히어로 영상이 나타나는 바로 그 프레임 — 에
11개 눈금이 이미 완성된 상태로 함께 있고 1번 눈금이 검정이다. 별도의 페이드인 스태거는 관찰 못함.

## 5. `<MegaMenuScrim>` — 내비 트리거 호버 → 본문 스크림 + 2단 메뉴

## 6. `<DimSiblingsNav>` — 호버한 항목이 아니라 **나머지가 흐려진다**

```jsx

  restColor="#393939"   // 휴식: 전부 이 색
  dimColor="#9b9b9b"    // 호버 중 형제
  ms={110}
/>
```

### 지시문

토스 헤더 내비의 호버 규칙은 **강조를 더하는 것이 아니라 빼는 것**이다.

휴식 상태에서 「서비스 · 비즈니스 · 회사소개 · 뉴스룸 · 채용」 다섯 항목의 최소 휘도는 **전부 57** 로 같다.

바뀌는 것은 **형제 항목의 글자색 하나뿐**이다.

이 방식의 장점은 항목이 몇 개든 **레이아웃이 1px도 움직이지 않는다**는 것이다.

## 7. `<AnchoredPopover>` — 버튼에 붙는 표면은 **오직 불투명도만** 바뀐다

```jsx

  anchor={ref}
  open={open}
  placement="bottom-end"
  dur={110}          // opacity 0 → 1
  transform={false}  // 관찰: scale·slide 없음
>
  {/* … */}
</AnchoredPopover>
```

### 지시문

앵커 버튼 아래에 흰 라운드 카드가 뜬다. **첫 프레임부터 최종 위치, 최종 크기**다.
슬라이드도 스케일도 없다. 변하는 것은 **불투명도 하나**뿐이고 90ms 안에 끝난다.

같은 컴포넌트의 두 인스턴스를 각각 쟀다.

| 인스턴스 | 트리거 | 휴식 | +45ms | +90ms |
|---|---|---:|---:|---:|
| 앱 다운로드 QR 카드 | `button[aria-expanded]` 클릭 | 119 | 129 (**9%**) | 229 (100%) |
| KOR 언어 드롭다운 | `button:has-text("KOR")` 클릭 | 152 | 198 (**49%**) | 246 (100%) |

카드 안쪽 빈 영역의 평균 휘도다. QR 카드는 QR 패턴 최소 휘도로도 244 → 225 → 29 로 같은 9% 를 얻었다.

둘 다 **90ms 완료**인데 중간값이 다르다. QR 카드는 시작이 느리고(가속형이거나 ~30ms 지연 뒤 빠른 페이드),
드롭다운은 거의 균등하다. 프레임만으로 「ease-in 인가 지연인가」는 구분 못함.
구현할 때는 **90~110ms, `--ease-standard`, opacity 만**이면 둘 다 재현된다.

셰브론(`KOR ▾`) 회전은 관찰 못함. 배경 딤(모달 오버레이)도 관찰 못함 — 본문은 그대로 선명하다.
드롭다운은 열린 순간 **KOR 이 검정, ENG 가 회색**으로 현재 값을 표시한다.

- `assets/motion/b-RouteSwap-company.webm` — 도착지 히어로가 스스로 등장한다.

### 우리 사이트 적용 위치 — **우리가 과한 쪽이다**

우리는 `src/index.css` 에서 `main` 전체에
`opacity 0 → 1`, `blur(5px) → 0`, `translateY(8px) → 0` 을 `--dur-enter`(400ms)로 건다
(`main[data-route-entering]`, `src/hooks/useReveal.js` 가 rAF 두 번으로 벗긴다).

측정(`b-our-route`, `/` → `/ai-college`):

| 프레임 | 최종 대비 차이 |
|---|---:|
| 000 (홈) | 24.21 |
| 001 (+45ms) | 4.26 — 새 페이지가 거의 안 보임 |
| 002 (+90ms) | 3.69 — 흐릿하게 읽힘 |
| 003 (+135ms) | 1.97 |
| 004 (+180ms) | 0.47 |
| 005 (+225ms) | 0.00 |

즉 **링크를 누른 뒤 약 135ms 동안 본문 전체를 못 읽는다.** toss 는 이 시간이 0 이다.
게다가 페이지 전체를 한 덩어리로 흐리게 만들기 때문에, 그 안에서 `[data-reveal]` 이 또 한 번
자기 애니메이션을 실행한다 — **연출이 두 겹으로 쌓인다.**

**권고: `main[data-route-entering]` 커튼을 제거하고 그 예산을 §2 `<WordCascade>` 로 옮긴다.**
전환은 없애고, 도착 페이지의 제목·부제·본문이 계단식으로 들어오게 한다.
읽을 수 있는 픽셀이 즉시 화면에 있으면서도 페이지가 살아 있는 느낌은 유지된다.

## 10. 우리 사이트 대조표 — 무엇이 부족하고 무엇이 과한가

| 대상 | toss (관찰값) | 우리 (관찰값) | 판정 |
|---|---|---|---|
| 히어로 미디어 | 인셋 16px·반경 40px → 스크롤 1800px 동안 풀블리드 | `.edge-wide` x=128·반경 20/28px **고정**, 스크롤 무반응 | **부족** — §1 축소판 도입 |
| 히어로 카피 | 어절 단위, **opacity/blur 만**, 위치 불변 | 줄 단위, `translateY(18px)` + blur 6px, 400ms | **과함**(translate) + **부족**(어절 단위) |
| 좌측 인디케이터 | 11개 앵커 눈금 14×2px, 활성 색, 호버 렌즈 +26px, 라벨 | 2px 브랜드 블루 **채움 막대**, `scaleY(progress)` | **성격이 다름** — §3 로 교체 |
| 섹션 이동 | 즉시 점프(50,964px 를 90ms) | `scroll-behavior: smooth` | **과함**(문서 3,413px 에 스무스는 느리다) |

| 메가메뉴 | 호버 → 스크림 72%@45ms + 제목→링크 2박자 | 없음 | **부족**(단, 2열 축소판으로) |
| 팝오버/드롭다운 | opacity 만, 90ms, transform 없음 | 없음(아코디언이 콘텐츠를 422px 밀어냄) | **부족** |
| 버튼 라벨 | 글자 세로 롤, 90ms, 배경 불변, **버튼 1개에만** | 배경색 120ms | 선택 사항 |
| 탭 전환 | (toss 에 동등물 없음) | opacity 0 + blur 4px + translateY 6px, **135ms 에 정착** | 적정 |

### 한 줄 요약

toss 의 화면 전환은 **큰 것을 하나 오래(스크롤 1800px 짜리 히어로 확장) + 작은 것을 여럿 아주 짧게(90~130ms)** 로 갈린다.
그 사이의 중간 길이 연출 — 200~400ms 짜리 페이지 단위 전환 — 은 **한 번도 관찰되지 않았다.**
우리 사이트는 정확히 그 중간 길이에 예산을 몰아 쓰고 있다.

### 관찰하지 못한 것

- 활성 눈금 색 전환의 정확한 지속 시간(120ms 보다 길다는 것만 확인).
- 홈 히어로 어절 간 지연의 정확한 값(20ms 미만).
- 호버·클릭 전환의 정확한 easing 곡선(45ms 격자로는 두세 점밖에 못 얻는다).
- 마우스가 빠져나갈 때의 역방향 타이밍(캡처 리그가 hover-out 을 찍지 않는다).
- `<RollLabel>` 의 글자별 stagger.
- 히어로 확장 span 1800px 이 `200vh` 인지 고정 px 인지(다른 뷰포트 높이에서 재검증 못함).
- 메가메뉴 패널의 그림자·라운드(흰 스크림 위라 경계가 생기지 않는다).
